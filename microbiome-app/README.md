# Microbiome Report

Interactive microbiome analysis that runs entirely in a browser tab. Load a feature table and metadata, get diversity, composition and differential abundance — **your data is never uploaded.**

MicrobiomeAnalyst, Nephele, Namco and MiCloud are all servers you upload to. That is a structural property of how they are built, and it is the reason many hospital IRBs and consent terms rule them out. This tool has no server.

## Quick start

```bash
npm install
npm run dev
```

Open the URL Vite prints, then click **Load demo data**.

## What it does

| | |
|---|---|
| **Inputs** | QIIME2 feature-table export, DADA2 seqtab, generic TSV/CSV, Excel `.xlsx`, MetaPhlAn (v3/v4, single or merged) |
| **Taxonomy** | QIIME2 `taxonomy.tsv`, one-column-per-rank files (mothur, DADA2, phyloseq, TaxAss), lineages embedded in feature IDs, or MetaPhlAn clade names |
| **Composition** | Stacked bars at any rank, top-N with the remainder pooled, facetable by metadata |
| **Alpha** | Observed, Shannon, Simpson, Inverse Simpson, Pielou, Chao1 — with Wilcoxon or Kruskal-Wallis |
| **Beta** | Bray-Curtis, Jaccard, Aitchison; PCoA; PERMANOVA with 999 permutations |
| **Differential** | CLR then Wilcoxon/Kruskal-Wallis per feature, Benjamini-Hochberg across features |
| **Export** | Every plot exports an SVG *and* the numbers behind it |

## What it deliberately does not do

- **Raw FASTQ processing.** Use QIIME2 or DADA2 upstream.
- **Phylogenetic metrics** (Faith's PD, UniFrac). They need a tree.
- **Covariates, random effects, repeated measures.** Those need MaAsLin 3; the plan is to run the real package under WebR rather than write a half-correct imitation.

## Three things it tells you that other tools do not

**Rank gaps are padded, never filled by shifting.** When a lineage skips a rank — `p__Cyanobacteria;o__Pleurocapsales`, with no Class — Order stays at Order and Class becomes null. Tools that shift lower ranks upward produce a taxonomy table that is wrong in a way nobody notices downstream.

**MetaPhlAn's stacked ranks are filtered, not summed.** MetaPhlAn output contains kingdom rows *and* phylum rows *and* species rows in one file, each summing to ~100% within its own rank. Summing without filtering double-counts everything.

**Count-only metrics are refused on relative abundance, with a reason.** Chao1 is estimated from singletons and doubletons; relative abundances contain neither. The tool says so rather than returning a number.

The diagnostics panel also reports mixed `d__`/`k__` conventions, stripped SILVA whitespace, samples dropped in the metadata join, and uneven sequencing depth.

## Known limitation worth understanding

**Aitchison distance is not scale invariant under the default zero replacement.** Adding a fixed pseudocount to `[10, 0, 5]` and to `[100, 0, 50]` gives non-proportional vectors, so sequencing depth leaks into the distances. It *is* invariant under multiplicative replacement. If your samples differ a lot in depth, prefer Bray-Curtis or switch the replacement strategy in `microbiome-core`.

## Demo data

`public/demo/` is synthetic, generated by `scripts/make-demo.mjs`: 64 features × 40 samples in two groups, with six genera shifted between them. It deliberately includes the messy cases the parsers exist to handle — a skipped Class rank, mixed `d__`/`k__` prefixes, SILVA-style trailing whitespace, uneven depth, and one missing metadata value.

Regenerate with `node scripts/make-demo.mjs`.

## Architecture

```
microbiome-core/   pure TypeScript, no DOM, zero dependencies
microbiome-app/    this React app
```

The core is a separate package so the statistics can be tested and versioned independently of the UI. Vite aliases `microbiome-core` to its source during development.

## Tests

```bash
npm test                            # app tests, against the demo data
cd ../microbiome-core && npm test   # unit tests for the statistics and parsers
```

Two further suites run against published datasets when the data has been fetched into `../validation/`, and skip cleanly otherwise — see the READMEs there.

The integration suite asserts on the biology: that planted taxa dominate the top of the ranking, and — more importantly — that **every genus clearing FDR is one that was actually planted**. A false positive there would mean the method is not controlling error.

Reference values in the core tests are analytic or come from R, with the call in a comment so they can be re-derived:

```
// R: wilcox.test(1:5, 6:10, exact = FALSE, correct = TRUE)
//    W = 0, p-value = 0.01216
```

## Deploying

`npm run build` emits a static `dist/`. It uses a relative base, so it works from any subpath — GitHub Pages included. No backend, no environment variables.

`npm run build:standalone` additionally writes `dist/microbiome-report-standalone.html`: one self-contained file with the JS, CSS and demo data inlined, which opens by double-clicking and can be emailed or put on a shared drive.
